PROBLEM SUMMARY - QR Gear Creator Page Issues
=============================================

PROJECT CONTEXT:
- Full-stack JavaScript app (React + Express + PostgreSQL)
- Uses Printify API for product fulfillment
- TanStack Query for data fetching
- Products have variants (size/color combinations) from Printify

ISSUES REPORTED:
1. Size/color selection not working - users cannot select or deselect size/color options
2. Cost/pricing not displaying
3. Images loading slowly (need pre-caching)

ROOT CAUSE ANALYSIS:

ISSUE 1 & 2 - Size/Color and Pricing Broken:
--------------------------------------------
File: client/src/pages/creator.tsx (approx lines 360-520)

The configurator reads legacy fields that don't exist:
- `selectedProduct.availableSizes` 
- `selectedProduct.availableColors`

But the Product schema (shared/schema.ts) uses:
- `printifyProductId`
- `blueprintId`
- `variants` (array of Printify variant objects with size/color info)

The size/color Select components get empty arrays and render disabled.

For pricing, the code calls `pricingMutation.mutate` with `selectedProduct.productLine`
but the server route `/api/pricing/quote` expects `blueprintId`/`printProviderId`.
The payload is rejected, `priceQuote` stays null, no cost displays.

SOLUTION NEEDED:
1. Derive unique sizes/colors from `selectedProduct.variants` array instead of non-existent legacy fields
2. Map variants on query resolve to extract available options
3. Pass correct identifiers (blueprintId, printProviderId) to pricing endpoint
4. Re-run quote mutation after size/color/hosting changes

ISSUE 3 - Image Caching:
------------------------
Images are fetched on every tab switch with no preloading.
Project uses TanStack Query which supports prefetching.

SOLUTION NEEDED:
- Use `queryClient.prefetchQuery` after products/templates queries resolve
- Implement Image() warmers in a useEffect to preload thumbnails
- Cache product and template images so mockups load instantly

ISSUE 4 - Printify API Connection Unstable:
--------------------------------------------
From server logs:
- `GET /api/admin/printify/catalog/5 500 in 197ms :: {"error":"Printify API error:...`
- Multiple 500 errors from Printify API calls
- Connection drops causing data to not load

The Printify integration is not stable - API calls fail intermittently.
This affects:
- Loading product catalog
- Getting variant/pricing information
- Creating orders

POTENTIAL CAUSES:
1. Rate limiting from Printify API
2. Missing or expired API token
3. No retry logic or error handling for failed API calls
4. No caching of Printify data (every request hits their API)

SOLUTION NEEDED:
- Add caching layer for Printify catalog data (it rarely changes)
- Implement retry logic with exponential backoff
- Add better error handling and user feedback
- Consider storing Printify product data in local database after first fetch

RELEVANT FILES:
- client/src/pages/creator.tsx - main product customization UI
- client/src/pages/admin.tsx - admin product management
- server/routes.ts - API endpoints including /api/pricing/quote
- shared/schema.ts - Product and variant type definitions

ADDITIONAL CONTEXT:
- The Product model has a `variants` JSONB column storing Printify variant data
- Each variant has properties like: id, title, options (size, color), price, is_enabled
- The pricing calculation needs to account for base product cost + customization options

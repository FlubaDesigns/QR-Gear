Claude — deep admin/products fix.

Goal:
Make admin/products build flow use the QRG-native master product options endpoint as the single source for colors, sizes, print locations, variants, and provider mappings.

Current broken flow:
1. ProductsModule loads products from /api/master-catalog.
2. BuilderContext.selectProduct() checks product.placements.
3. If placements are missing, it manually calls:
   GET /catalog/placements?provider=printify&blueprintId=...&printProviderId=...
4. useCreatePacket.ts pulls availableSizes/availableColors directly from selectedProduct.
5. useCreatePacket.ts still hardcodes:
   QRG_BLUEPRINT_BLANK_CODES = { 12: '101' }

This is wrong. It bypasses the QRG schema.

============================================================
CORRECT FLOW
============================================================

When a product is selected in admin/products:

1. Resolve canonical docId:
   selectedProduct.docId

Example:
qrg_11111

2. Call:

GET /api/admin/master-catalog/products/qrg_11111/options

3. Store returned data on selectedProduct / builder state.

4. UI uses only that hydrated selected product for:
   - sizes
   - colors
   - placements / print locations
   - qrgVariants
   - provider mappings

5. Packet creation uses:
   - product.qrgBlankId
   - product.docId
   - selected size/color codes
   - selected placement IDs

No blueprint-to-QRG mapping in client. Ever.

================================================================
1. FIX AFFILIATE IDENTITY RESOLUTION
================================================================

Problem:
The external session flow still appears to create sessions with affiliateUserId blank or unresolved.

This is a core business problem because the whole model depends on:
“25% of profit goes to the user ID / affiliate / host”

Required fix:
When creating a BuilderSession, resolve affiliate identity from canonical ownership.

Preferred resolution order:
1. explicit affiliate user attached to placement
2. affiliate owner attached to host
3. fallback owner attached to store/host policy if explicitly allowed
4. otherwise reject affiliate-enabled session creation

Do NOT leave affiliateUserId blank if revenue sharing is enabled.

Required behavior:
- if placement has revenue split enabled, affiliateUserId must resolve
- if it cannot resolve, session should either:
  - fail with clear error
  - or proceed with no-affiliate mode only if policy explicitly allows it

Add clear runtime checks for:
- builderHostId
- builderPlacementId
- affiliateUserId
- pricingPolicyId
- revenueSplitId

2. ADD SESSION → CART ENDPOINT
================================================================

Problem:
The subsystem currently supports placement load, surface load, session creation, draft save, and pricing compute.
It does NOT yet appear to support a real “add configured item to cart” path.

Add endpoint:

POST /public/embed/session/:sessionId/cart

Purpose:
Turn a configured embedded builder/store session into a real cart item.

Payload should include:
- selected product / surface
- selected variant
- design selections
- QR selections
- quantity
- preview/config snapshot

Required behavior:
- validate session
- validate placement
- validate host
- validate surface readiness
- validate selected variant
- compute pricing snapshot
- attach attribution context
- create cart line item with immutable pricing + attribution snapshot

Cart item must preserve:
- builderHostId
- builderPlacementId
- builderProfileId
- affiliateUserId
- surfaceId
- pricingPolicyId
- revenueSplitId
- pricing snapshot
- configuration snapshot

6. ENFORCE DOMAIN / HOST / PLACEMENT VALIDATION
================================================================

Problem:
allowedDomains exists on BuilderHost, but public runtime enforcement is not yet proven strongly enough.

Add strict validation to all public embed/session/cart/buy routes:

Required checks:
- placement exists
- host exists
- profile exists
- surface exists

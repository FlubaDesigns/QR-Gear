============================================================
CORE PROBLEM
============================================================

We are experiencing field-name drift across:
- admin/products
- catalog transforms
- design builders
- autosave
- packets
- renderers
- picker components

Example failure:
- catalogToSelectItem writes:
  `colorsAvailable`
- DesignColorPicker reads:
  `availableColors`

This causes:
- silent UI failures
- autosave corruption
- packet inconsistencies
- renderer mismatch
- component desync
- schema drift

The root problem is:
components are inventing/adapting field names locally.

That is forbidden going forward.

============================================================
CANONICAL FIELD AUTHORITY
============================================================

Provider/raw/schema fields are NOT UI fields.

ALL transformations MUST happen through:
- adapters
- mappers
- normalizers

UI/view-model fields are canonical.

Components may ONLY consume canonical fields.

============================================================

============================================================

------------------------------------------------------------

Forbidden:
- aliasing fields inside components
- supporting multiple field names
- fallback field guessing
- local renaming
- conditional field probing

BAD:
------------------------------------------------------------
item.availableColors || item.colorsAvailable || []
------------------------------------------------------------

GOOD:
------------------------------------------------------------
item.availableColors
------------------------------------------------------------

If the field is wrong:
FIX THE ADAPTER.
NOT THE COMPONENT.

4. IMPLEMENT ADAPTER MAPPING
============================================================

  item: ProviderCatalogItem

    id: item.id,

    imageUrl: item.imageUrl,
